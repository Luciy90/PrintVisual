## Целевая архитектура первого этапа

1. `src/app.ts` собирает Express-приложение, включает `helmet`, `cors`, JSON body parser, логирование и маршруты `/api`.
2. `src/routes/*` содержит тонкие route handlers:
   - `/api/health`;
   - `/api/settings`;
   - `/api/printers/mac`;
   - `/api/network/scan`;
   - `/api/network/recovery-plan`.
3. `src/services/*` содержит бизнес-логику:
   - хранение настроек в `data/printerCamsV2.json`;
   - получение MAC через Moonraker/Klipper endpoints;
   - сканирование подсетей и сопоставление `saved MAC -> discovered IP`.
4. Текущий `print 1.8.28.html` сохраняется как frontend-клиент и постепенно начинает использовать `/api/...`.
5. Старый режим запуска как локальный HTML не удаляется сразу; API-вызовы должны иметь fallback на текущую клиентскую логику.
