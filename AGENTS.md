## 2. Важное ограничение браузера

Обычный один HTML-файл, запущенный в браузере, не может напрямую читать ARP-таблицу, выполнять настоящий ICMP/ping-скан и получать MAC-адрес любого устройства в локальной сети.

Поэтому реализация должна быть двухуровневой:

1. Базовый вариант без внешнего сервера: HTTP/WebSocket-проверки доступности IP-адресов и получение MAC из API самого принтера. Для Klipper/Moonraker проверены `/machine/system_info` и `machine.system_info`; они работают из браузера, если приложение открыто с origin, разрешенного в `cors_domains` Moonraker, например `http://localhost:*`.
2. Расширенный резервный вариант для настоящей системной карты `IP -> MAC`: локальный помощник на машине пользователя, браузерное расширение или уже существующий локальный backend, который сможет выполнить ARP/сетевое сканирование и вернуть результат в HTML-приложение. Для текущего Klipper/Moonraker-сценария этот вариант не является обязательным.

План ниже рассчитан так, чтобы базовая логика не ломалась, а место под расширенный сканер было предусмотрено заранее.
